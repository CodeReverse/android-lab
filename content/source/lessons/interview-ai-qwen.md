## 1. 什么场景适合固定流程，什么场景适合 Agent？

原帖位置：第 1 项。

### 参考回答

步骤明确、审计要求强、业务状态转移严格时优先显式流程；信息收集路径不确定但结果可验证时可让模型选择动作。把确定性权限、资源限制与提交环节固化，只把确实需要弹性判断的部分交给模型。开放循环多了失败路径，也增加验证与恢复成本。

### 原理与继续追问（编辑扩展）

追问：如何证明需要 Agent？与同工具集合、同预算的固定流程比较任务完成率和维护成本，特别看长尾问题和失败恢复。若简单路由已经达标，就没有证据为更复杂方案付费。

继续学习：[控制权与选型](#/article/ai-agent-runtime)

## 2. 模型编造工具动作时，系统如何约束？

原帖位置：第 2 项。

### 参考回答

只允许注册的工具与明确 schema；执行器独立做身份、资源和业务校验。检索及工具结果作为不可信数据，不能改变上层权限。模型说“已经操作”时需对照真实操作结果；模型猜的金额、账号或资源 ID 都必须核验。固定边界越清楚，开放规划越可控。

### 原理与继续追问（编辑扩展）

追问：加一句不要幻觉够不够？不够。提示词是概率性影响，授权和实际状态应来自确定性服务。把注入文本加入工具返回值，测试是否诱发越权调用，结果进入发布门禁。

继续学习：[工具与信任边界](#/article/ai-tools-context) · [安全评测](#/article/ai-quality)

## 3. 如何控制 Agent 的循环和终止？

原帖位置：第 3 项。

### 参考回答

预算上设置步数、时间、token 和费用上限，语义上检测目标完成、无进展和不可恢复错误。重复调用要区分合法轮询与失控循环：轮询有独立退避、次数和状态规则。终止时保留已确认结果和未完成原因，不输出虚假成功。

### 原理与继续追问（编辑扩展）

追问：每次都有新文本算进展吗？不算。按已完成子目标、新增可靠证据与外部状态变化判断；重复改写同一计划没有实际进展。恢复后保持 run ID、预算和动作记录，避免靠重启无限刷新上限。

继续学习：[终止与状态机](#/article/ai-agent-runtime)

## 4. 拿到工具调用 JSON 后，代码层还要做什么？

原帖位置：第 5 项。

### 参考回答

解析并验证工具名、参数类型和必填项；解析当前身份，检查资源归属和业务规则；生成调用关联与必要幂等标识，执行工具，保存标准化结果，再交给后续步骤。读写工具可使用不同权限，日志不能直接落完整凭据和敏感参数。

### 原理与继续追问（编辑扩展）

追问：校验和执行之间状态变了怎么办？关键条件要在真正写入的后端事务中再次校验，必要时采用版本号或条件更新；只在 Agent 进程预检查不消除 TOCTOU 竞态。

继续学习：[调用链](#/article/ai-tools-context) · [可靠执行](#/article/ai-agent-runtime)

## 5. 工具参数错误应如何恢复？

原帖位置：第 6 项。

### 参考回答

语法或 schema 错误可以给出有限、结构化反馈要求修正；业务无权限或禁止操作应直接拒绝；对象过期可请求重新查询或澄清。设置最大修正次数并记录失败类型。不要把错误详情中的密钥、内部栈或其他用户数据回给模型。

### 原理与继续追问（编辑扩展）

追问：参数是合法格式但指向错误对象呢？需要身份、上下文和业务校验，必要时让用户明确目标。格式约束只保证形状，无法知道“这个订单是不是用户真正要取消的订单”。

继续学习：[参数与业务验证](#/article/ai-tools-context)

## 6. 工具失败时怎样重试，如何避免重复副作用？

原帖位置：第 8 项。

### 参考回答

先区分确定失败、临时故障和结果未知。查询可以退避重试；写入超时先查状态，用幂等键重放同一个业务意图，禁止每次生成新键。保留外部操作 ID、动作意图和结果记录，必要时补偿或转人工。重试预算与整体 deadline 绑定，避免雪崩。

### 原理与继续追问（编辑扩展）

追问：幂等键怎样定义？应绑定同一业务动作，不是每个网络尝试；服务端校验同键参数一致，明确保留时间和重复请求结果。不同动作不能误共享键，过期后重试也需要对账。

继续学习：[检查点与副作用](#/article/ai-agent-runtime) · [幂等基础](#/article/network-reliability)

## 7. Skill 怎样划分粒度，怎样证明有效？

原帖位置：第 9 项。

### 参考回答

Skill 可以作为任务知识、流程和资源的可复用封装，其具体格式依产品而异。围绕可独立验收的任务定义输入、输出、适用条件、错误恢复和例子；太宽难维护，太细增加选择成本。它不是把一段自然语言放入文件就获得可靠执行能力。

### 原理与继续追问（编辑扩展）

追问：怎样评测？同模型、同任务集、同预算比较有无 Skill 的成功率、误调用、步骤、成本与回归；加入不适用任务检查是否错误触发。用独立验收规则，不能让 Skill 作者凭印象自评。

继续学习：[Skill 与上下文](#/article/ai-tools-context) · [实验设计](#/article/ai-quality)

## 8. Harness 解决哪些模型之外的问题？

原帖位置：第 10 项。

### 参考回答

Harness 是支撑模型完成任务的运行环境与控制机制，包括上下文构建、工具执行、预算、持久状态、验证、隔离、观测和恢复。模型决定下一步的能力只是其中一项。长任务更需要保存可靠进度与可回查证据，避免上下文耗尽后重复工作或误认为已完成。

### 原理与继续追问（编辑扩展）

追问：用了 Agent 框架就齐了吗？框架提供原语，但业务权限、外部副作用幂等、模型漂移回归和环境边界仍需应用实现。检验 Harness 应用中断、错误工具返回和目标不可达等故障注入，而非只演示顺利完成。

继续学习：[Harness 定义](#/article/ai-tools-context) · [恢复机制](#/article/ai-agent-runtime)
