## 1. 一次网络读取不是一条模型消息

模型 API 可以等完整答案后一次返回，也可以生成一部分就推送一部分，这叫流式响应。流里不一定每个事件恰好一个 token，也可能包含状态或工具参数。SSE（Server-Sent Events）是 HTTP 上的一种文本事件流格式，客户端需要按事件规则组装数据，不能把“流式”理解成随意拼字节。

聊天回答流式显示时，最容易写出 `read bytes → parse JSON → append`。但网络分块可能在任意位置切开：一个 UTF-8 字符、一个 JSON 字段，甚至 SSE 的分隔行都可能跨两次读取。TCP/HTTP 传输边界不等于应用事件边界。

```text
收到块 1：data: {"text":"你
收到块 2：好"}\n\n
正确处理：增量解码 → 按协议组装完整事件 → 解析 JSON
```

这里为了展示分块，省略了实际字节编码。不能每块都独立解码字符串再丢弃未完成字节，也不能遇到一行 data 就假定整个业务响应结束。

## 2. SSE 只定义事件流，不定义模型业务

一个教学事件可以是：

```text
id: 17
event: delta
data: {"text":"你好"}

```

SSE 按行解析字段，用空行结束并派发事件；多个 data 行按规则拼接，注释和重连字段有各自语义。具体标准见 [WHATWG SSE](https://html.spec.whatwg.org/multipage/server-sent-events.html)。`delta`、JSON 中的 text 和某些服务使用的结束标记则是业务协议，不是 SSE 自动规定。

因此客户端需要两层状态机：传输解析器产出完整事件，业务解析器识别文本增量、工具调用参数片段、完成或错误。HTTP 连接正常结束不必然意味着模型业务成功；若缺少明确完成事件，应按协议判断是否中断。

## 3. 会话状态需要归属和完成条件

```text
Idle → Connecting → Streaming → Completed
                         ├→ Failed
                         └→ Cancelled
```

每轮生成有 requestId 和 conversation/generation 身份。取消旧轮后开启新轮，迟到片段必须按身份丢弃，不能继续拼到新答案。若服务发的是累计快照，不能当增量追加；若是增量，重复重放又会导致文字重复。两者需要在协议上明确。

UI 不必为每个 token 触发一次昂贵重排。可短时间合并可见更新，但底层完整事件仍要按序处理；缓冲要有上限。客户端 backpressure 能减少本地堆积，不一定让远端立即停止计算，需要服务端取消接口或断连处理配合。

## 4. 取消、断连和重试不是同一件事

取消界面展示、关闭 HTTP 流、停止服务端生成、撤销工具副作用是四层动作。关闭连接只确定本地传输结束，服务是否停止要看契约；已经执行的工具调用不能靠断连回滚。

SSE 的事件 ID/Last-Event-ID 能用于恢复位置，但前提是服务保存并支持重放对应事件。不是每个模型 API 都提供可续传任务。没有恢复协议时，应明确显示中断并重新发起一轮，而不是把新生成文本无缝接到旧文本，伪装成同一个完成结果。

副作用重试必须有稳定操作 ID 与可查询结果，机制见 [弱网重试](#/article/network-reliability?section=3)。即便只是生成文本，重复请求也可能产生额外费用和不同答案，需要向用户表达真实状态。

## 5. 工具参数拼完整后才能进入执行边界

模型可能逐段输出工具名和参数。片段看起来像合法 JSON 的前半部分，不代表最终调用已完成。应等待完整调用事件，按 schema 解析与校验，再由宿主执行授权和业务检查。

```text
模型建议调用 → 参数完整/合法 → 权限与业务校验
 → 记录 operationId → 执行 → 记录真实结果 → 回传模型
```

模型输出不能授予自己权限。用户仅要求查订单时，模型建议取消订单也不能自动扩大授权。工具失败要回传结构化原因，不能编造成功结果来维持对话流畅。运行机制继续见 [Agent](#/article/ai-agent-runtime)。

## 6. 用切片和迟到事件验证客户端

教学测试可把同一个合法流按每个字节位置切开，确认结果与不切片一致；再覆盖多 data 行、注释、半个 JSON 后断连、重复事件、取消后迟到和工具参数分片。检查 UI 状态、资源关闭与重复副作用，而不是只看文字能显示。

网络取消要连接到协程及底层 Call，清理响应体和监听器；具体所有权见 [OkHttp](#/article/okhttp-chain?section=5)。本文描述协议与测试设计，没有调用付费模型或宣称已运行设备测试。
