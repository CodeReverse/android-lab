## 阅读方式

按定义、结构、运行过程、实现细节、故障与验证逐层阅读。问题顺序由本站编写；文末面经映射只证明相应主题被问过，不代表原帖出现了本篇全部追问。每问下方即为对应讲解。

## 第 1 问：AI 流式接口与普通一次性 JSON 有什么区别？

生成式服务可能持续返回文本增量、结构化事件、工具请求与最终完成状态。客户端需要区分连接已建立、首个有效输出、持续生成、等待工具、完成、失败与用户取消。仅用 loading=true/false 难以表达半截结果与结果未知。

渲染增量时不要每个字符都全量解析 Markdown 并替换整个列表。可以按合理节奏合并 UI 更新，同时保留原始事件顺序。节流改变展示频率，不应丢弃必须处理的协议事件；文本与控制消息可采取不同处理策略。

## 第 2 问：SSE 事件边界为什么不等于网络分包？

SSE 按文本行和空行定义事件，TCP 读取块可能把一个事件拆成几段，也可能一次包含多个事件。解析器应缓冲不完整数据，正确处理 UTF-8 跨块、多个 data 行和事件终止。不能对每次 read 的字符串直接当成完整 JSON。

事件 ID 与 Last-Event-ID 可以参与恢复，但服务端必须提供对应保留与重放语义。盲目重连可能重新开始生成、重复计费或重复执行工具；应使用会话 ID、生成 ID 与序号管理去重和续传。没有恢复协议时，明确显示中断状态比静默拼接两次独立回答更可靠。

## 第 3 问：取消生成为什么不一定取消已执行工具？

用户停止生成，需要终止客户端读取并向服务端表达取消意图，但在途工作和已执行工具未必被撤销。对发送邮件、购买或删除等有副作用工具，授权应由可信业务逻辑判断，必要时展示明确用户确认，并提供幂等操作 ID。

模型返回的工具名与参数是不可信输入。验证 schema、权限、参数范围与当前会话身份，不允许模型通过自由文本扩大权限。工具结果里的网页或文档也可能夹带指令，不能把检索内容当作更高优先级的控制命令。

## 第 4 问：端云分工怎样依据质量、隐私与性能确定？

云侧通常负责模型调用、长期凭据、权限与审计；客户端负责交互、生命周期与必要的本地能力。不要把服务端长期密钥放进 APK。端侧推理可降低部分延迟与数据外传，但受模型体积、内存、算力、温度和设备覆盖限制，应准备能力检测与降级。

对端侧模型，量化可能降低体积与带宽成本，也可能影响效果；加速器支持与算子回退会影响实际速度。首次加载和持续运行的热状态都要测试，不能用一次高端机冷跑推断全量体验。

### 逐层追问与回答支点

- 流式显示完成如何判定？依协议完成事件，不以 socket 暂时没数据或界面有句号判断。
- 首 token 快就代表体验好吗？还要看完整任务耗时、输出质量、失败恢复、工具等待与成本。
- 用户离开页面是否保留生成？由产品语义决定工作归属，并给返回页面一个可恢复状态。

## 第 5 问：怎样验证断流、重连、取消与过期响应？

切分每一种事件的字节边界，注入乱序/重复应用事件、网络中断、取消竞态与超大输出；工具侧测试权限拒绝和重复调用。该知识库未运行真实模型或采集用户数据，本文提供工程设计与验证方法。
