## 1. 可达性与垃圾判定

GC 主要根据对象的可达性等规则判断回收资格，而不知道业务是否还需要它。一个页面已经关闭，但仍被长生命周期 listener 强引用，业务上无用，运行时仍可达。两个对象互相引用但没有从根可达的路径，可以成为可回收对象，因此可达性分析能够处理引用环。

“我把局部变量设为 null”只是移除一条引用；别的路径仍在时不会解决泄漏。

## 2. GC Roots 与存活对象

根是运行时认为必须作为追踪起点的一组引用来源，例如活跃线程栈／寄存器中的引用、运行时管理的类或静态相关引用、JNI 全局引用等；精确集合取决于运行时与收集阶段。沿强引用边可达的对象需要保留，软弱虚引用按各自规则处理。

根不是“所有 static 变量永不回收”的同义词。类与类加载器能否卸载、线程是否结束、native 引用是否删除都影响对象图。堆分析应把根路径和生命周期一起解释。

## 3. 清除、复制与整理

标记识别活对象；清除回收死亡对象，可能留下碎片；复制或整理移动存活对象，便于形成可用空间，但需要更新引用和相应暂存／目标空间。收集器可以组合这些策略，而不是只属于教科书中的一个盒子。

有空闲总量也可能因连续区域、分配约束或收集阶段而无法满足某次申请。是否碎片导致失败要看实际收集器和失败证据，不能从一次 OOM 就直接推断“内存不连续”。

## 4. 分代与跨区引用

许多负载中对象寿命呈现大量短命的特征，分代利用这一经验让回收聚焦更可能死亡的区域；它不是对所有程序都绝对成立的规律。老对象仍可能引用年轻对象，因此局部收集必须知道跨区域引用。

实现可通过写屏障记录相关引用变化，用 card table、remembered set 等结构帮助定位跨区边，具体颗粒度和结构依收集器。写屏障是引用更新时维护 GC 信息的代码机制，不等于 JMM 的内存屏障。

## 5. 并发标记与屏障

会存在一致性挑战：收集器看到的是持续变化的对象图，必须用屏障、快照语义或增量更新等策略维持正确性。以经典三色理解法，若处理过的对象新增指向尚未标记对象的边，同时原路径消失，不记录变化就可能漏标。

SATB 思路记录被删除的旧引用等信息，帮助保留标记起点快照相关的可达性；增量更新则关注新增边等变化。实际算法比颜色图更复杂，还涉及新分配对象与阶段切换，不能断言所有 GC 都用同一套屏障。

## 6. 并发收集与 STW

并发表示某些工作与业务线程同时推进，收集器仍可能在根处理、阶段转换等环节暂停。并行表示多个 GC 工作线程同时工作，与是否暂停用户线程是不同维度。

暂停、总 GC CPU、内存余量和吞吐之间有取舍。一个低暂停方案可能需要更多并发工作与内存；只看最长停顿不能完整判断用户体验。达到 safepoint 的等待等运行时因素也应和 GC 本身分开观察。

## 7. G1 的 Region 与回收

以 JDK 21 G1 为明确基线，它把堆划为 region，根据区域角色与收益组织分代回收；并发标记帮助识别老区存活信息，young/mixed 等收集阶段按相应策略疏散存活对象。remembered set 等用于帮助处理跨区引用。

暂停目标是规划目标，不是实时保证。存活集合过大、分配速度高、疏散空间不足、巨型对象或 CPU 竞争都可能破坏期望。调参前先看日志中的阶段、存活量和失败原因，不按网上一组参数覆盖所有应用。

## 8. 引用类型与资源关闭

强引用保持普通可达性；软引用有内存敏感的保留语义，但不适合作为可预测容量的业务缓存；弱引用用于不阻止回收的关联；虚引用通常配合队列观察相应处理阶段，不能用 get 拿回对象。具体时序要遵守 API 与运行时规则。

文件、连接和 native 资源优先显式 close 或受控所有权释放。GC 不知道业务何时最适合归还资源；清理回调可作兜底但不保证及时。不要使用 finalize 承担关键资源生命周期。

## 9. 分配压力与回收频率

大量短命对象会造成分配压力与频繁回收，即使回收后存活平台稳定也可能卡顿；泄漏则更关注不该存活的对象持续保留。两者可能同时存在，需要分配速率、回收后存活量与引用证据。

System.gc 不是“立刻全部回收”的确定性契约，也不能回收仍强可达的业务垃圾。反复主动请求回收可能增加开销。先减少重复分配、限制缓存与并发峰值、修复所有权，再决定是否有特定可证实场景需要额外措施。

## 10. Android 与 OOM 的诊断衔接

可达性、所有权和分配压力的思路可迁移，但不能把 G1 region、HotSpot 参数和某个停顿模型直接当作 ART 实现。Android 还需观察 Java/native/图形内存与系统低内存行为，ART 的收集策略随系统版本变化。

验证时保留运行时版本、GC 日志、分配曲线、回收后存活量、根路径与业务轨迹，再做单变量对照。具体看 [ART 内存](#/article/memory-art) 与 [OOM](#/article/oom-diagnosis)。本文是机制推演，未执行 GC 或耗尽实验。
