## 1. 高层交互与语义

点击不是只有按下和抬起，还包含取消、语义动作、交互反馈、焦点及键盘等行为。高层组件或 clickable 提供常见契约；pointerInput 适合确实需要定制手势的场合。自己识别坐标后调用 onClick，可能让屏幕阅读器和键盘用户无法操作。

收藏按钮应优先使用带选择状态的合适组件；绘图板则可能需要多指、压力或自定义轨迹。判断粒度是“需求缺了哪项能力”，而不是低层 API 看起来更专业。[手势抽象层级](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/understand-gestures)。

## 2. 命中、事件传递与消费

开始时依据命中测试建立接收链，后续事件沿相应路径分发。Initial、Main、Final pass 使父子能够分别预处理、处理和观察消费结果；消费标志供其他处理方协作判断，不意味着事件对象从传播系统中消失。不要把它完全套成 View 的单一拦截回调。

在可横滑行内部放按钮，按下后移动超过手势阈值，行开始拖动，按钮应撤销点击。排查重复点击时记录手指 ID、pass、位移、消费状态与取消，而不是只打印 DOWN/UP。多个顶层挂起识别器顺序写在同一块中，前一个长期循环可能让后一个永远执行不到；按 API 契约组织独立处理。

## 3. pointerInput 的 key 和生命周期

key 改变会重新启动相应输入处理逻辑，因此影响中的手势可能被取消。若拖动每一帧更新的位移恰好被当作 key，就可能造成自己不断打断自己。真正改变手势身份或配置时需要重启，仅希望回调更新时可用合适的最新值读取方式。

推演拖拽文章行：业务 ID 应稳定，位置数值则随手势改变；删除该项应终止输入；账号切换后不能把旧项的松手事件提交到新账号。输入的生命周期与业务提交的幂等性是不同层的问题，不能只靠协程取消解决两者。

## 4. 嵌套滚动的距离分配

把可用滚动量看作有符号预算：父预消费一部分，子消费其可处理部分，剩余再交父后消费。fling 类似地协商速度。父不能报告比实际处理更多的消费，也不能把方向约定弄反，否则会有抖动、吞滚动或边界跳跃。

例如折叠标题先消耗上滑位移直到最小高度，其余交给列表；列表到顶下拉后，剩余位移再展开标题。嵌套滚动协议解决协作，不解决无界高度：把 LazyColumn 放在同方向无界滚动父中，仍需明确尺寸或合并为一个列表。[嵌套滚动](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/scroll)。

## 5. 文本编辑状态

输入过程还涉及选区、光标和输入法组合区。过早把拼音中间态当成提交文本，或异步格式化后用旧字符串覆盖，都可能造成丢字、光标跳动。状态式文本 API 与基于 value/onValueChange 的 API 有不同用法，应选定版本和方案；不能混用互相竞争的状态源。

搜索框可把编辑态及时交回 UI，再从规范化后的查询产生防抖请求。校验与过滤需要考虑粘贴、选中替换和 IME 组合，不宜每次强制把光标移到末尾。焦点请求由明确交互触发，避免在函数体每次重组都抢焦点。业务上“请求完成”通常也不意味着应把用户的键盘收起。[文本输入](https://developer.android.com/develop/ui/compose/text/user-input)。

## 6. IME、Insets 与窗口适配

窗口可用空间会随键盘、系统栏、分屏和折叠变化；内容需要基于实际约束适配，而不是设备型号或固定屏幕宽度。Insets padding 会影响可见区域与滚动，多个层级重复处理可能产生双倍留白。Scaffold 的内容 padding 与系统 Insets 的职责要明确，不能各层盲目叠加。

表单末行获得焦点后，要验证键盘出现仍能看见光标、滚动可达、返回键行为正确。双栏设备上焦点导航次序应符合阅读与任务顺序。布局能够压缩不代表外接键盘、读屏和鼠标也能用。[Insets](https://developer.android.com/develop/ui/compose/system/insets)、[焦点行为](https://developer.android.com/develop/ui/compose/touch-input/focus/change-focus-behavior)。

## 7. 交互边界验证

按下不抬起后导航离开、拖动中删除目标、输入法组合中旋转、超大字号下展开键盘、键盘 Tab 操作收藏，分别检查取消、状态归属与可达性。测试不是越多截图越好，而是覆盖每种输入所有权转换。

如果只有真机偶发丢点击，先捕获输入序列和主线程阻塞，区分识别器消费错误、坐标错误和处理延迟；若截图显示正常但读屏失败，检查语义动作而非继续改布局。参照[测试文章](#/article/compose-testing)设计断言，实验结果需自行采集。
