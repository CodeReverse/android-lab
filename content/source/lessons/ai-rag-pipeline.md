## 1. 从一份政策 PDF 走到可检索证据

RAG 是 Retrieval-Augmented Generation，即检索增强生成：先从外部资料找相关片段，再把问题与片段一起交给模型回答。它通常不在每次提问时重新训练模型，而是改变本次输入上下文。Chunk 是被索引的文档片段，embedding 是用于匹配的向量表示，二者不是同一种东西；基础区别见 [AI 基础](#/article/ai-foundations?section=6)。

用户问“试用期能否报销设备”，答案在 PDF 表格脚注中。直接按固定字符数切开文本，可能把“可报销”与“仅适用于正式员工”的条件分开，检索命中主句却丢了限制。

RAG 不只是向量库加模型。先解析标题、段落、表格、脚注与来源位置，把每个片段保留文档 ID、版本、页码/段落锚点、权限和更新时间。原研究见 [RAG](https://arxiv.org/abs/2005.11401)；下面的文档工程属于教学实现设计，不把全部细节归为原论文结论。

## 2. 切块是上下文完整性与检索粒度的取舍

大块保留条件但可能带入无关内容、降低精确命中；小块更聚焦，却容易失去指代和表格标题。先按文档结构切，再为必要上下文添加标题或邻近段，而不是无条件加大量重叠。

```text
文档 v3 / 设备报销
片段 A：申请条件 + “试用期不适用”
片段 B：额度表 + 表头 + 适用范围
元数据：docId, revision, section, sourceAnchor, ACL
```

重叠可以减少边界断裂，也会增加存储与重复召回。向量模型/tokenizer 改变后，旧 embedding 与新 query embedding 未必兼容，需要索引版本与重建计划；不能只替换模型文件就继续混用。

## 3. 权限与版本在召回之前就要生效

用户只能访问部门 A 的政策，应在检索候选产生和后续处理中执行对应权限，避免未授权文本进入模型或日志。仅生成后过滤答案太晚，因为内容已经进入上下文；过滤方式还会影响 ANN 召回质量，需要按检索引擎能力验证。

当前问题要求 v3，旧 v2 不能只因向量更相似就优先。可用元数据过滤、版本优先与冲突提示组合，但要保留历史查询场景。删除文档时索引、缓存与引用可用性都要更新；否则源站删了，检索缓存仍泄露旧内容。

这是系统权限与数据一致性设计，不是模型提示能独自完成的工作。客户端权限原则可类比 [Android 信任边界](#/article/android-security)，具体企业权限仍需与自己的身份系统对接。

## 4. 召回、重排与上下文各自做一道筛选

关键词适合精确名词/编号，向量适合语义表达，混合召回可覆盖二者。重排模型再对 query 与候选片段联合评分，减少粗召回误差；最终还要去重并保留必要条件，不能简单把前 K 条原样塞满窗口。

```text
问题 → 权限/版本约束 → 多路召回
 → 融合 → 重排 → 去重/补条件 → 有预算的证据集合
```

为什么不直接 K 取很大？噪声、重复和矛盾会占用上下文，拉高延迟，并可能干扰生成。扩大召回池与扩大最终上下文是两个独立参数。HNSW、RRF 和 reranker 的工作方式见 [检索底层](#/article/ai-retrieval)。

## 5. 生成要能回到具体证据

给每个进入上下文的片段稳定引用 ID，要求关键结论对应到它；渲染时用受控映射生成真实链接，不让模型任意编造 URL。回答“试用期不适用”应指向支持该限制的条款，不只是文档首页。

```text
结论 C1 → 证据 E4（v3，第 2 节脚注）
结论 C2 → 未找到充分证据 → 不作确定断言
```

引用存在仍不证明支持，需检查声明是否被证据蕴含、是否遗漏否定和适用范围。文档中的指令样文字属于不可信内容，不能改变工具权限或系统行为。对冲突证据应说明版本/范围，不能默默挑一个方便的答案。

## 6. 故障按链路定位，更新按版本发布

若答案漏了试用期条件，先看解析是否保存脚注，再看召回是否命中、重排是否丢弃、上下文是否截断，最后看模型是否误解。每层保存可脱敏的证据与配置，避免只留最终答案。

更新时先构建新索引，在固定评测集上比较，确认可切换后发布并保留回退指针；文档权限撤销则可能需要更快的即时失效通道。不要把每次增量更新都当成无需验证的小改动。本文没有实际运行索引或报告准确率，质量检查见 [AI 质量](#/article/ai-quality)。
