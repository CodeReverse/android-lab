## 1. 外部入口与攻击面

导出的 Activity、Service、Receiver、Provider、深链、WebView 与文件共享都可能接收外部输入。第一步盘点哪些入口确实需要外部访问，再设置最小暴露与相应权限。不能因为 Intent 来自某个看似正常包名，就直接信任其参数。

客户端校验提升体验与减少误操作，服务端仍须独立校验账号、资源所有权与业务权限。APK 可以被分析，不能把隐藏接口或混淆后的常量当作安全边界。

## 2. 凭据全生命周期

长期服务端密钥不应嵌入客户端。短期用户令牌需考虑存储、刷新、注销、日志与备份；Android Keystore 能保护某些密钥材料，但不意味着进程内所有使用结果都不会泄露，也不能阻止有权运行的代码滥用业务能力。

退出账号要处理内存、磁盘缓存、后台任务与订阅。加密缓存仍需要账号隔离，日志也应避免记录 Authorization、完整 URL 敏感参数和用户正文。故障排查不能以无差别采集敏感数据为默认前提。

## 3. Deep Link 与 Intent 校验

对 URI 使用正规解析，检查 scheme、host、path 与必要参数，避免字符串 contains 的伪域名绕过。即使链接经过验证，目标页面仍要校验当前用户是否有权访问指定资源。登录跳转后的恢复也要防止开放重定向或把任意地址送入高权限 WebView。

PendingIntent 应根据业务明确可变性和目标组件，避免给外部调用者不必要的修改空间。Provider 文件共享需限制路径与授权期限，不能为方便直接暴露整个内部存储目录。

## 4. 安全收紧与兼容迁移

权限与后台限制随 targetSdk 和系统版本演进，迁移时应阅读对应行为变化。为了兼容旧 SDK 全局打开明文通信或放宽全部导出组件，往往会扩大风险。应定位具体依赖、最小例外范围与替代方案。

证书校验失败时，正确动作是检查域名、信任链、时间、代理与服务端配置，不能在正式构建里使用接受全部证书的实现。调试环境的特殊信任也要与发布构建隔离。

## 5. 权限与账户切换验证

以一个订单 Deep Link 为例，测试未登录、他人订单、非法 host、嵌套重定向、账号切换和进程恢复。再检查日志与备份中是否存在不必要的凭据或数据。本文给出工程原则，具体合规要求需要结合项目实际规定。
