## 1. 先从熟悉的函数理解模型

假设要预测一次图片处理耗时。普通程序可以写 `time = pixels * costPerPixel + overhead`，我们手工选择规则和常数。机器学习保留某种计算结构，却让数据帮助确定其中的参数。

一个极简模型是 `ŷ = wx + b`：x 是输入特征，ŷ 是预测，w/b 是可调整参数。训练数据给出若干 x 与实际 y，训练过程寻找让预测误差较小的参数；推理则用已得到的参数计算新输入。这里的“模型”既包含计算结构，也包含学到的参数，不是一个装着所有答案的数据库。

人工规则更透明、便于保证明确约束；学习模型适合难以逐条写清的模式，但依赖数据分布与验证。真实耗时受设备、缓存和并发影响，单个 x 显然不够；我们用它只是为了看清训练过程。基础资料见 [Google 线性回归课程](https://developers.google.com/machine-learning/crash-course/linear-regression)。

## 2. 手算一次训练，区分预测、损失与更新

为便于演算，只用 `ŷ = wx`，暂时没有 b。教学样本 x=2、y=6，初始 w=1：

```text
前向计算：ŷ = 1×2 = 2
损失：L = (ŷ-y)² = (2-6)² = 16
梯度：dL/dw = 2(wx-y)x = 2(2-6)×2 = -16
学习率 η=0.1，更新：w_new = w - η×梯度 = 2.6
再次预测：ŷ_new = 2.6×2 = 5.2
新损失：(5.2-6)² = 0.64
```

损失把“错多少”变成一个可优化数值；梯度表示参数小幅变化时损失怎样变化；沿负梯度方向走一小步，是梯度下降的基本思想。学习率太大可能越过合适范围而不稳定，太小则推进慢。上面一次下降只是这个样本与步长的结果，不保证所有训练每一步都下降。

真实训练通常以 batch 处理多个样本，多轮遍历叫 epoch，优化器负责依据梯度更新参数。反向传播用链式法则高效计算多层参数的梯度，不是把正确答案反向写进一个字符串表。训练循环可对照 [PyTorch 参数优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)。本文数值是手算，没有运行神经网络训练。

## 3. 多个输入自然引出向量与矩阵

一个输入不够，加入图片像素量 x1 与并发任务数 x2：`ŷ = w1x1 + w2x2 + b`。把输入写成向量 x=[x1,x2]、权重写成 w=[w1,w2]，点积就是对应分量相乘再相加。

教学取 x=[2,3]、w=[4,1]、b=1，输出为 `2×4 + 3×1 + 1 = 12`。一个向量只是有顺序的数值列表，不天然代表“语义”。矩阵可以把多个这样的计算排在一起；例如输入有 3 个 token、每个 4 个数，形状记作 `[3,4]`，不是三个数值都等于 4。

Tensor 是更一般的多维数组概念。图像可以有批次、高、宽、通道等维度；不同库的维度顺序可能不同，所以形状和轴含义必须同时说明。这为后面的 `QKᵀ`、模型参数量与内存估算准备语言，暂时不需要先学完全部线性代数。

## 4. 神经网络为什么要多层和非线性

将输入乘矩阵、加偏置，再经过非线性函数，得到一层输出；多层组合逐步构造表示。最简单的 ReLU 把负数变成 0、保留正数。若只有线性变换连续相乘，无论堆多少层，仍可合并成一个线性变换，不能仅靠层数表达更复杂关系。

```text
输入 x → 线性变换 W1x+b1 → 非线性
       → 线性变换 W2h+b2 → 输出
```

这张图是简单前馈网络，不代表 Transformer 的完整结构。层中的权重/偏置属于模型参数；学习率、batch 大小、层数等设计选择通常称超参数。所谓“7B 模型”通常指约 70 亿参数，不能仅由参数数目推断知识量、任务正确率或设备速度。

深度学习是使用多层神经网络的一类机器学习方法，LLM 是其中面向语言、规模较大的模型类别；AI 范围更广，还包含其他技术路线。结构入门见 [Google 神经网络课程](https://developers.google.com/machine-learning/crash-course/neural-networks)。

## 5. 语言怎样变成数值，生成怎样变成概率

Tokenizer 按特定词表/规则把文本转成 token ID，embedding 表把 ID 映射成向量。token 不是固定一个汉字或一个英文单词；同一文本在不同 tokenizer 下长度可能不同。Tokenizer 必须与模型配套，见 [Hugging Face Tokenizers](https://huggingface.co/learn/llm-course/en/chapter2/4)。

模型计算后得到词表中各候选的 logits，也就是未归一化的分数。softmax 把分数变成和为 1 的分布。教学词表只有 A/B/C，logits 为 `[0, ln2, ln1]`，指数值为 `[1,2,1]`，概率就是 `[0.25,0.5,0.25]`。

贪心策略选最高概率 B；采样策略按分布选择，因此可能选 A 或 C。选出的 token 加到历史中，再预测下一个，直到停止条件。高概率表示在模型与上下文条件下更倾向这个延续，**不是这个说法为真的概率**。这一步区别是理解幻觉与评测的关键。

## 6. 上下文、参数与记忆分别存在哪里

用户说“刚才我提到的版本”，模型只有在请求中仍包含相关信息，或宿主从外部存储取回它时，才能据此回答。普通推理请求通常不会把本次对话写进模型权重。

|载体|保存什么|何时改变|
|---|---|---|
|模型参数|训练得到的数值规律|训练/适配或替换模型|
|上下文窗口|本次输入的消息、证据、工具结果等|宿主构造下一次请求|
|外部记忆/数据库|持久事实、历史、文档与任务状态|应用按权限读写|
|KV Cache|当前推理中可复用的中间计算|处理 token、清理或复用缓存|

上下文有长度预算，超出的内容需要选择、检索或摘要；摘要会丢失信息，也可能写错。KV 不是长期用户记忆，更不是训练参数，具体工作方式见 [推理第 2 节](#/article/ai-inference?section=2)。embedding 也不是“把整份知识无损压进去”，向量的意义由训练目标与使用方式决定，见 [Embedding 入门](https://developers.google.com/machine-learning/crash-course/embeddings)。

## 7. 泛化与幻觉让验证不可省略

模型在训练样本上很好，却在新设备、新语言或新文档上变差，可能是过拟合或输入分布变化。训练集用于更新参数，验证集帮助选择配置，独立测试集估计未参与选择的数据表现；如果反复看测试集调参，它就逐渐失去独立性。

语言模型的目标与生成机制不自动提供逐条事实核验。它可能续写出格式正确却没有来源的答案；降低温度只能改变选择策略，不能把缺少的事实变出来。应用需要检索、工具、拒答、结构校验和评测各自承担责任，不能只写“请不要胡说”。

一个简单反例是询问今天仓库的依赖版本：模型训练时不可能知道你刚修改的文件，应使用授权的文件读取工具获取事实。即使模型猜对一次，也不能把猜测流程当可靠设计。

## 8. 把 AI 应用拼回熟悉的软件系统

```text
用户输入
 → 宿主程序：身份、会话、预算、上下文
 → 可选检索：取允许的证据
 → 模型：生成文本或工具调用提议
 → 可选工具：宿主校验后执行真实操作
 → 验证结果 → 展示/保存状态
```

RAG 主要把外部证据带入生成；工具调用把结构化动作连接到真实能力；Agent 让后续动作随观察动态决定。它们可以组合，不是只能三选一。框架帮忙组织代码，不能替代正确权限、事务、取消和测试。工作流与 Agent 的区别见 [官方工程讨论](https://www.anthropic.com/research/building-effective-agents)。

建议接着读 [从函数到 Agent 的完整例子](#/article/ai-agent-workshop)，先掌握应用运行链；需要理解模型内部时再读 [Transformer](#/article/ai-transformer)。端侧则主要改变模型执行位置与资源约束，不会让上述宿主职责消失。这条顺序不要求先懂深度学习训练全部细节。
