## 1. 用一个私人文档助手建立学习主线

设想给现有应用增加私人文档助手：离线找资料，在线解释复杂问题，还能语音提问。先不选框架，把任务拆成“找到证据、理解问题、给出结果、必要时执行动作”。每一步都可能用更简单的实现，学习路线由尚未解决的问题推进。

本专题有 20 篇 AI 学习文章，覆盖通用模型、应用系统与端侧，不把范围局限于 Android SDK。另有四份公开面经的 26 道 AI 节选解答。进度与练习保持可选，下面是依赖关系，不是必须顺序打卡的清单。

## 2. 先让用户找到原文，再决定是否生成

建议先用 [AI 基础](#/article/ai-foundations) 建立“函数→参数→训练→概率→上下文”的概念，再运行 [从函数到 Agent](#/article/ai-agent-workshop) 的无 API key 示例。前者解释模型是什么，后者解释应用怎样围绕模型工作；之后再按下面的问题链选择专篇。

用户只问某个配置键在哪，关键词检索可能足够；换成同义表达才引出 embedding；文档很多时引出近似索引；多个候选互相冲突时需要版本与重排。这条链可从 [检索第 1 节](#/article/ai-retrieval?section=1) 走到 BM25、HNSW、RRF 的具体演算。

找到原文后，若用户需要综合解释，再把受权限约束的证据送入生成模型。切块不能切掉否定条件，引用必须支持具体声明。继续读 [RAG 全链路](#/article/ai-rag-pipeline)，用 [RAG 与评估入门](#/article/ai-evaluation) 的正确证据替换实验区分检索失败与生成失败。

这一步的学习产出是一张可检查链路：文档版本→解析片段→候选→上下文→声明与引用。没有证据的答案应标明边界，而不是靠更流畅的措辞掩盖。

## 3. 生成变慢以后回到模型内部

长文输入首字慢、长对话内存涨，会推动我们学习 token、Attention 与自回归生成。先在 [Transformer](#/article/ai-transformer?section=2) 手算一次加权，再到 [推理第 3 节](#/article/ai-inference?section=3) 算 KV Cache，解释上下文、批量与 KV heads 怎样改变内存。

若只是缺最新知识，不急着训练；行为格式不稳定、偏好不合适时再读 [训练与适配](#/article/ai-training)，区分 SFT、LoRA/QLoRA、DPO 与 GRPO。服务并发增加后，才进一步进入 [服务调度](#/article/ai-serving)，说明排队、连续批处理和投机解码的收益条件。

这一步不是记算法全称，而是能回答“删掉缓存会怎样”“降权重位宽为什么不自动缩小 KV”“吞吐高为什么仍有人等很久”。具体公式和反例都在对应正文。

## 4. 从回答到行动，需要另建执行协议

文档助手若升级为修改配置或提交任务，文本正确不再足够。模型提议工具，宿主校验并执行，真实结果回到任务状态；超时、崩溃与重复执行必须有恢复语义。

```text
回答问题 → 证据支持度
执行任务 → 授权 + 参数 + 副作用 + 完成证据
```

先读 [Agent 状态机](#/article/ai-agent-runtime?section=3)，再读 [工具、MCP 与上下文](#/article/ai-tools-context)。代码修改用 [AI Coding](#/article/ai-coding) 的独立验证器与仓库约束检查，不能把模型的完成声明当成真实测试通过。

客户端还要正确处理 SSE 分片、迟到事件与取消，见 [流式客户端](#/article/ai-client)。这些协议与普通客户端并发、网络基础相连，却仍归在各自分类，避免检索时混在计算机网络目录中。

## 5. 离线要求把模型成本带回设备

离线先提供检索原文，确需生成才评估模型能力与设备预算。按 [端云架构](#/article/ai-edge-architecture) 算权重、KV 与工作区；按 [引擎选型](#/article/ai-edge-runtime) 验证转换、后端落点和数值；再用 [量化](#/article/ai-quantization) 比较误差与真实速度。

能加载模型只是第一关，连续使用还要经过 [端侧性能与发布](#/article/ai-edge-performance) 的温升、资源、生命周期和回退验证。增加语音/视觉时，继续到 [多模态](#/article/ai-multimodal) 处理采集速率、时间戳和坐标，而不只换一个模型名字。

最终用 [AI 质量工程](#/article/ai-quality) 为每次改动保留固定失败集、证据支持度与任务成功条件。以上均为学习设计，未声称已完成设备推理、训练或线上实验。
