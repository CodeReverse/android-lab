## 面经是采样，不是完整课程

面经记录受岗位、团队、候选人简历与记忆影响。多次出现说明值得重视，但不能据少量公开帖子计算行业真实概率。实习面经中的基础问题也可能在资深面试出现，只是追问会进一步落到复杂约束、取舍和治理。

本知识库把面经当作选题信号，把官方文档、规范和源码作为原理入口，再按资深岗位责任补齐内容。本文是一份编辑判断，不是某家公司 P7 的正式能力标准；不同公司和职级体系不应直接等同。

## 必须形成闭环的四层能力

第一层是机制解释：能够从 API 追到状态、线程、数据结构和调度，说明适用版本。第二层是工程设计：能给失败、取消、恢复和兼容制定协议。第三层是问题定位：能从现象提出可证伪假设，用证据找出根因。第四层是长期责任：让同类问题更难复发，并用真实指标说明收益和代价。

例如协程题从 suspend 状态机开始，往下追到取消与异常传播，再落到旧请求不覆盖新页面，最后延伸为统一异步接口与故障观测。不是每题都需要背到 CPU 指令，但不能在关键机制上用模糊词跳过因果。

## 按分类选择入口

| 领域 | 应能解释的核心 | 应能交付的工程证据 |
| --- | --- | --- |
| Android | 消息、IPC、生命周期、渲染、内存 | 一次恢复测试或故障等待链 |
| 网络 | 解析、传输、认证、缓存与重试 | 分阶段时序与幂等恢复验证 |
| Java/Kotlin | 内存模型、集合、协程与 Flow | 一个并发不变量和交错测试 |
| Compose | 状态、Snapshot、组合身份、编译与阶段 | 固定版本下的机制推演和性能对照 |
| 跨端 | 共享层、渲染模型、边界协议 | 同场景对照、采用范围与退出方案 |
| AI | 事件协议、工具权限、检索与评测 | 失败样本、质量回归与成本限制 |
| 五项资深能力 | 决策、定位、治理、演进、成果归因 | ADR、trace、实验、迁移与复盘 |

算法维持独立的 LeetCode 中国原题清单，不为扩大篇数增加未经面经映射确认的题目。解题时补充复杂度、边界与测试即可，不把每种技术场景都转成刷题。

## 12 年经验如何选择性复习

已有熟练项目经验的领域，可以直接从文末的“面试提炼”检查是否能解释机制与证据；答不上来再回读对应正文。长期未接触 Compose 编译与 Runtime，可以按 State → Snapshot → 组合结构 → Compiler → Phases → Effects 顺序读，再进入原来的专项路线查缺补漏。

如果项目讲述薄弱，先写真实证据卡，再补支撑该项目的技术机制。若只按知识点顺序读到最后才准备项目，很容易积累大量术语却没有可证明的个人贡献。进度与练习保持可选，阅读不需要被打卡流程打断。

## 内容深度与当前边界

本批正文覆盖关键机制与工程推演，附文末复习提问及验证设计；它不是已经在全部 Android 版本执行过的源码实验全集。源码入口需要按你实际项目版本继续固定，示例实验需要真实运行后才能形成个人证据。原有路线中尚无对应正文的细项会保留为资料，不冒充已完成课程。
