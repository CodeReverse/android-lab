## 1. 模型输出函数名并不等于函数执行

工具可以是你写的查询函数、搜索 API 或文件读取器；schema 是机器可读的参数约束，比如订单 ID 必须为字符串。模型看到的是工具描述与参数格式，实际数据库连接和权限仍由应用掌握。先走过 [Agent 完整例子第 2–4 节](#/article/ai-agent-workshop?section=2)，再看 MCP（Model Context Protocol，模型上下文协议）等接入方式，会更容易区分各层。

用户要查询订单，模型输出 `getOrder({id:"O17"})`。这是一份调用提议，真正读取数据库的是宿主或工具服务。Function Calling 的价值在于让意图成为结构化参数，但 schema 合法只证明形状符合约定，不证明订单存在或用户有权访问。

```text
模型提议 → 参数校验 → 用户/资源授权 → 工具执行
 → 结构化结果/错误 → 返回给模型继续处理
```

把这一层分开，才能限制能力、记录真实结果和处理取消。若模型在参数中写 `admin:true`，宿主不能将其视为权限来源。

## 2. MCP 标准化连接，不接管全部业务

以固定版本 [MCP 2025-11-25 架构规范](https://modelcontextprotocol.io/specification/2025-11-25/architecture) 为基线：Host 管理用户交互、策略和多个 Client，Client 与 Server 建立相应连接，Server 暴露能力。协议使用 JSON-RPC 等约定，包含能力协商和生命周期。

工具、资源与提示模板各承担不同角色；MCP 让客户端发现和调用工具，不等于自动授予工具所有权限，也不等于统一解决任务记忆或模型训练。具体 [Tools 规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) 描述 schema 和调用结果等契约；实现还需遵守其安全与交互要求。

为什么不用每个工具自定义 HTTP？少量固定能力可以很简单；统一协议在多来源接入时减少重复适配，却增加协议版本、连接与能力治理。是否采用应根据生态与维护成本判断。

## 3. 工具设计要让错误可以被纠正

一个 `executeAnything(command)` 很灵活，却难以限制影响和解释失败。`findOrder`、`prepareRefund`、`submitRefund` 等窄能力可以把读取、准备与提交分开，但也要避免拆得过碎导致大量往返。

工具输出应说明成功/失败类别、可重试性、结果身份和必要证据；不要把所有失败都塞进一个自然语言字符串让模型猜。重试同样要区分安全查询、幂等写入和结果未知。工具的描述帮助模型选择，宿主的校验才决定是否执行。

```json
{"status":"conflict","resourceVersion":8,"retryable":false,
 "message":"订单状态已变化，需要重新读取"}
```

这是教学输出结构，不是 MCP 规定的通用业务格式。它让下一步重新读状态有依据，而不是盲目重发写入。

## 4. Skill、Memory 与 Harness 不在同一层

Skill 通常是可复用任务说明与配套资源/工具的组织方式，不是 MCP 的同义词，也不天然改变模型权重。Memory 保存跨轮可恢复的信息；Harness 是围绕模型组织工具、状态、检查、预算和环境的执行系统。不同产品定义有差异，不能把某家的文件格式当通用标准。

以代码任务为例：Skill 描述项目发布步骤，Memory 记录已确认的项目约束与进度，Harness 决定何时运行测试、如何保存 checkpoint、失败后如何恢复。长任务设计可参考 [Agent harness 实践](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)。

## 5. 上下文窗口是有限工作区

把所有日志和工具返回原样塞入上下文，会挤掉任务约束和关键证据。应区分长期事实、当前计划、原始证据与临时结果：原文保留在可回查存储，摘要携带来源、版本和不确定性，再按需取回。

摘要会丢失细节，也可能把假设写成事实。压缩前后的状态应保留“已完成/待验证/失败/未授权”区别，不能把“建议提交”缩成“已提交”。跨用户记忆还需作用域、过期、删除和隐私控制；不能默认一段历史适用于所有账号。

外部网页、文件和工具文本是不可信数据，即便包含“忽略之前规则”也不应变成宿主指令。上下文整理与权限执行必须分层，提示本身不能替代沙箱。

## 6. 用契约测试验证工具接入

教学测试覆盖 schema 缺字段、越权资源、超时、取消、重复 toolCallId、协议不兼容和恶意工具结果。检查宿主是否拒绝不合法操作、保留真实失败、释放连接，并能在必要时向用户请求明确输入。

完成一次工具调用的证据是服务返回与副作用状态，不是模型的完成声明。MCP 兼容测试、业务契约测试和端到端任务测试各有范围，不能互相替代。本文没有接入真实业务工具或执行外部动作。
