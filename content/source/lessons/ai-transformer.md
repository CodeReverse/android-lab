## 1. 语言模型与生成过程

语言模型预测的是给定前缀后的下一个 token 分布，不是直接在数据库中查找整句话。Tokenizer 将文本映射为 token ID，Embedding 将 ID 映射为向量，若干 Transformer 层更新表示，最后输出词表 logits，经解码策略选择下一个 ID，再重复。中文的一个字不一定是一个 token；模型、词表、规范化策略不同，长度、截断和成本都会变化。文本前后相同但分词结果不同，缓存也不能直接复用。

以包含三个位置的句子推演数据流：输入长度 T，隐藏维度 D，某个注意力头的维度 d。不要只背 Q、K、V 三个字母，要说明 Q 是当前位置用来匹配的表示，K 是被匹配的位置表示，V 是聚合的信息，三者都是从输入通过可学习线性投影得到。

## 2. Q、K、V 与注意力计算

单头忽略批次时，Q、K、V 的形状为 T×d。分数 QKᵀ 是 T×T；除以 √d 后加 causal mask，对每一行做 softmax，再乘 V，结果仍为 T×d。缩放缓解点积随维度增长导致 softmax 过度饱和的问题，不意味着训练永远没有梯度问题。因果掩码将未来位置屏蔽；padding mask 屏蔽补齐位置，二者目的不同。

多个头并行学习不同表示，再拼接并投影。残差为梯度与信息流提供通路；归一化稳定数值尺度；FFN 在每个位置进行非线性特征变换，通常占有大量参数。具体采用 LayerNorm 还是 RMSNorm、Pre-Norm 还是 Post-Norm，必须对照目标模型配置，不能把一种实现当成所有 Transformer 的定义。

训练时已知整段真值，可以用 teacher forcing 在一个前向中并行计算各位置的下一词损失；有 causal mask 仍然能并行。推理时下一个 token 尚未产生，常规自回归生成必须迭代。“Transformer 可并行”不等于一口气生成未知的所有输出。

## 3. RoPE 与相对位置

RoPE 将 Q、K 每两个通道看成二维向量，按位置和通道频率旋转。位置 m 与 n 的旋转向量点积可转化为与相对差 n−m 有关的形式。因此位置信息进入注意力匹配，而不是简单给 token 加一个整数。典型实现对 Q/K 旋转，V 不做同样操作；具体以架构为准。

能计算更长位置的旋转角，不代表模型在训练范围外仍准确。长上下文还受注意力分布、训练数据、位置缩放方案、KV 内存与中间信息提取能力限制。业务上要用长文中部证据、多跳问答、数字和表格测试，不能只证明“接口接受了 100K token”。

## 4. 采样策略与事实正确性

temperature 调整 logits 的相对尖锐程度；top-k 保留若干候选；top-p 按累计概率保留候选集合。更低温度可能减少随机性，但错误事实也可能具有最高概率。temperature=0 常被接口解释为贪心策略，实现细节与非确定性内核仍会影响复现。

模型更大、上下文更长、RAG 或微调都不是事实正确性的充分条件。事实任务应提供可追溯证据，限制无依据回答，并用明确测试检验。模型输出“我有 99% 把握”不是校准概率。应通过历史标注集、分类校准或业务规则估计风险。

## 5. KV 缓存与 MoE

**为什么 decode 只缓存 K/V，不缓存旧 Q？** 新位置只需要自己的 Q 去匹配历史 K，再聚合历史 V；旧位置的输出在因果模型里不会被新 token 反向改写，所以通常不用再算旧 Q。详见 [KV Cache](#/article/ai-inference)。

**MoE 激活参数少，能否据此认为内存也少？** 不能。路由可能每次只选部分专家，但部署通常仍要存储全部专家权重，跨设备还可能引入通信和负载不均。激活计算量、总参数、驻留内存是三个指标。

**如何验证自己理解了 mask？** 用很小的序列手算掩码矩阵，改变未来 token，检查前面位置的 logits 在 eval 模式下是否保持一致；再改变 padding 长度检查有效位置。这个实验验证因果边界，不验证模型知识正确性。本文未实际执行该实验。
