## 1. 文字先变成模型可计算的序列

先修只需要理解向量、矩阵形状和“用固定参数做一次计算”。如果这些概念尚不熟悉，先读 [AI 基础第 1–5 节](#/article/ai-foundations?section=1)；本篇在此基础上解释语言模型内部，不要求先会训练模型。

输入“帮我总结这段日志”，模型并不直接对中文字符执行注意力。Tokenizer 先按模型词表切成 token ID；一个字可能对应一个或多个 token，多个字符也可能合成一个 token。因此字符数、字数和 token 数不能互换，模型与 tokenizer 必须配套。

ID 再查 embedding 表，得到每个位置的向量。设教学输入只有三个 token，隐藏维度为 4，得到矩阵 `X[3,4]`。它不是检索到三条文字定义，而是可训练的数值表示。后续各层不断根据上下文更新这些表示，最后预测下一 token 的分布。

本文以常见自回归 Transformer 解释，不表示所有模型结构相同；原始 [Transformer 论文](https://arxiv.org/html/1706.03762v7) 还是 encoder-decoder 架构，不能把现代 decoder-only 的所有细节归给它。

## 2. Attention 用当前问题给历史信息加权

这里的“线性投影”就是矩阵乘法：把输入的多个数按不同权重组合成新的数。例如 x=[1,2]，投影矩阵两列分别为 [1,0] 与 [1,1]，得到 [1,3]。矩阵中的系数是模型参数；Q/K/V 使用不同矩阵，所以同一个 token 可以产生三种承担不同职责的表示。若 X 是 [n,d]、Wq 是 [d,dk]，Q 就是 [n,dk]；Q 乘 K 的转置，得到 [n,n] 的位置匹配分数。

从 X 线性投影出 Q、K、V。可以把 Q 理解为当前位置寻找信息的查询，K 是各位置参与匹配的表示，V 是匹配后聚合的内容；这只是理解角色的类比，不是数据库键值存储。

```text
Q = X Wq，K = X Wk，V = X Wv
scores = Q Kᵀ / sqrt(dk) + mask
weights = softmax(scores)
output = weights V
```

以一个查询和两个候选演算，缩放及遮罩处理后的 scores 假设为 `[0, ln(3)]`，softmax 得到 `[0.25, 0.75]`。若两个 V 分别为 `[2,0]`、`[0,4]`，输出就是 `[0.5,3]`。这些是人为小数值，目的是说明注意力在算加权内容，不是在硬选唯一一个词。

除以 sqrt(dk) 用于控制点积尺度，避免维度增长让 softmax 过于尖锐等问题。自回归训练的 causal mask 阻止当前位置读取未来目标，否则训练会偷看答案，推理却拿不到相同信息。

## 3. 多头与前馈层各自增加什么能力

一个头在一组投影空间里聚合，多头允许不同投影学习不同关系，再拼接并投影回隐藏维度。不能保证“第一头一定学语法、第二头一定学指代”；那是需要分析证据的解释，不是架构契约。

Attention 主要在位置之间交换信息，逐位置的前馈网络进一步变换特征。残差连接提供跨层信息/梯度路径，归一化帮助数值与优化稳定；具体层顺序、激活与归一化类型因模型而异。看模型代码时应先画一层的张量形状，再看堆叠数量，避免只背模块名。

GQA 让多个 query head 共享较少的 K/V heads，减少 KV 存储与相关读取，但不是把所有 Q 也合成一个头。结构依据 [GQA 论文](https://arxiv.org/abs/2305.13245)，它与缓存大小的关系将在 [推理第 3 节](#/article/ai-inference?section=3) 演算。

## 4. RoPE 把位置关系带进 Q 与 K

如果只看内容向量，相同 token 在不同顺序中的关系难以表达。位置方案可以是加位置 embedding，也可以变换 Q/K。RoPE 在成对维度上按位置旋转：

```text
一对分量 [x,y] 在位置 m：
x' = x cos(mθ) - y sin(mθ)
y' = x sin(mθ) + y cos(mθ)
```

不同维度对使用不同频率。由于旋转矩阵的性质，位置 m 的 Q 与位置 n 的 K 做点积时，能体现相对位移 n−m 的作用。这解释了为什么它与注意力点积分数相关，而不只是给 token 追加一个整数序号。推导见 [RoFormer / RoPE](https://arxiv.org/html/2104.09864v5)。

可以不用 RoPE，采用其他绝对/相对位置机制，各有训练与外推特性。RoPE 也不保证无限长上下文质量；超出训练分布时仍要评估缩放策略、注意力模式和任务表现。

## 5. 一次生成为何仍要逐步推进

最后一层输出经词表投影得到 logits，再按温度、top-k/top-p 等策略形成采样选择。温度改变分布尖锐程度，不能把错误知识变正确；贪心解码也不等于事实可靠。

```text
输入 tokens → 模型 → 下一 token t1
输入历史 + t1 → 模型 → t2
继续直到停止条件或预算
```

训练可以在带因果遮罩的已知序列上并行计算多个位置的预测损失；生成时下一个输入依赖刚选出的 token，因此有自回归依赖。KV Cache 复用历史计算，减少重复工作，却没有消除这个依赖。

## 6. 用形状和反例检查理解

拿一个短序列，写出 X、Q、K、V、分数矩阵和输出形状；把未来位置 mask 去掉，说明为何训练条件改变；把 KV head 数缩小，再推导缓存成本。这样比背“Attention 是 QKV”更能解释实际系统。

Attention 权重本身不能直接证明因果解释，长上下文能装下内容也不证明模型能正确使用。本文数值均为教学演算，未执行训练或性能实验。事实问答需要证据与评测，继续读 [RAG 链路](#/article/ai-rag-pipeline)。
