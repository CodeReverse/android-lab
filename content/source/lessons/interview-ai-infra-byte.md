## 1. 怎样系统地加速大模型推理？

原帖位置：第 2 项。

### 参考回答

先分解排队、prefill、decode 与后处理，再根据请求长度、batch 和硬件判定计算或带宽瓶颈。对共享长前缀可以缓存，对显存碎片与并发可评估分页 KV 和连续批处理，对注意力 IO 可评估 FlashAttention，对权重流量可评估量化。投机解码要测草稿成本和接受率。不同优化针对不同资源，不能把这些名字当作可无条件叠加的加速倍数。验收同时看 TTFT、TPOT、P99、质量与每成功任务成本。

### 原理与继续追问（编辑扩展）

追问：吞吐提高而用户更慢如何解释？更大的 batch 可能提高 GPU 利用却拉长 token 间隔，排队也可能增长。固定到达过程与长短请求分布做回放，单独画排队时间和执行时间；达到吞吐目标但超出交互 SLO，应调整准入和调度，而不是宣布优化成功。

继续学习：[服务与调度](#/article/ai-serving) · [推理机制](#/article/ai-inference)

## 2. 压缩模型有哪些路径，量化有什么实际收益？

原帖位置：第 3 项。

### 参考回答

量化减少表示位宽，剪枝减少部分结构，蒸馏训练更小模型学习目标行为。量化可能降低文件、权重流量与内存，并在有合适内核时提升执行效率。PTQ 成本相对低，QAT 在训练中适配量化误差但投入更大。压缩要比较同任务质量门槛下的资源，不能仅凭模型小了就判断成功。结构化剪枝更容易映射常规硬件；非结构化稀疏是否获益取决于内核。

### 原理与继续追问（编辑扩展）

追问：INT4 为什么慢于 FP16？查看是否出现低效解包、反量化、算子 fallback、图切分和同步；还要看输入规模是否足以摊销调度。质量损失则沿校准分布、异常值、敏感层和分组逐步定位。文件大小、峰值内存与时延是三个独立验收指标。

继续学习：[量化与压缩](#/article/ai-quantization)

## 3. 权重、激活和 KV 分别量化，省的是什么？

原帖位置：第 4 项。

### 参考回答

权重常驻并反复读取，降低精度主要减少参数占用和流量；激活影响中间张量与计算路径，低精度内核可能进一步受益；KV 随上下文与有效并发增长，量化主要扩大缓存可容纳范围。W4A16 只描述权重与激活，不能推断 KV 精度。元数据、对齐、未量化层和工作区都让整体收益小于简单位宽比例。

### 原理与继续追问（编辑扩展）

追问：哪一个优先？短上下文小并发、权重主导时先评估权重；长上下文并发中 KV 可能主导。K 误差影响注意力分数，V 误差影响聚合输出，需长序列与业务质量测试。不能只测困惑度就宣称工具调用没有退化。

继续学习：[量化误差](#/article/ai-quantization) · [资源预算](#/article/ai-edge-performance)

## 4. KV Cache 的原理是什么，分页缓存为什么有用？

原帖位置：第 5 项。

### 参考回答

因果 decoder 中历史 K/V 不因后续 token 增加而变化，所以保存它们，当前 Q 只需匹配历史 K 并聚合 V。这样省下重复前缀计算，但每步全注意力仍访问随序列增长的历史。PagedAttention 用逻辑块到物理块映射分配 KV，减少连续分配产生的碎片并方便共享，提高可服务并发；并不减少模型需要关注的 token 数。

### 原理与继续追问（编辑扩展）

追问：怎么估算缓存？标准配置为 2×层数×序列数×长度×KV头数×每头维度×元素字节。32 层、4096 长、8 个 KV 头、128 维、单序列 FP16 得 512 MiB。GQA、滑窗、共享前缀和混合架构要按实际形式调整；页尾和块表也有开销。

继续学习：[KV 公式与分页](#/article/ai-inference)

## 5. 前缀缓存能缓存什么，何时失效？

原帖位置：第 6 项。

### 参考回答

相同有效 token 前缀的 K/V 可以复用，以跳过重复 prefill。缓存兼容条件还包括模型、适配器、位置和影响前向的配置；不是两段人类看起来意思相同就能命中。前缀开头放动态时间戳可能破坏后续复用。它不等于缓存最终答案，也不保证 decode 加速。租户与权限边界需要显式设计。

### 原理与继续追问（编辑扩展）

追问：知识更新后要清吗？如果只是同样 token、同样模型的纯前向 KV，外部知识变化并不会神秘改变其数学结果；但若应用上下文、检索内容或权限变了，就必须重新构造正确请求和隔离缓存。最终回答缓存则更直接依赖知识与业务时效。

继续学习：[Prefix Cache](#/article/ai-inference) · [缓存与路由](#/article/ai-serving)

## 6. 一个可用的 Agent 包含哪些模块？

原帖位置：第 7 项。

### 参考回答

最小闭环包括目标与状态、上下文构造、模型决策、工具注册与执行、结果观察、完成验证及终止控制。生产还要持久检查点、预算、权限、日志和恢复。LLM 返回调用参数是建议，宿主校验并执行；业务成功由实际状态判断。工具错误、超时与未知结果要区分，避免让模型无限反复尝试。

### 原理与继续追问（编辑扩展）

追问：做了 checkpoint 为什么还可能重复创建订单？外部写入完成、检查点未提交就崩溃，恢复后看不到成功记录。应有幂等键、外部操作 ID 和对账；框架保存状态无法单独提供跨系统 exactly once。

继续学习：[Agent 状态机](#/article/ai-agent-runtime) · [工具边界](#/article/ai-tools-context)
