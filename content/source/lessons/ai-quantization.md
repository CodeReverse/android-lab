## 1. 从浮点值映射到有限整数

bit 是一位二进制，4 bit 最多表达 16 个编码，8 bit 最多 256 个；FP16 是一种 16 位浮点格式，INT8 是 8 位整数表示。量化不是把 16 个字节随便压成 4 个字节的通用压缩，而是减少数值的可表示精度，再用尺度映射回需要的范围。需要先区分权重与运行期数组，可读 [AI 基础第 6 节](#/article/ai-foundations?section=6)。

模型权重占用太大，量化用有限离散值近似原值。常见仿射量化写成：

```text
q = clamp(round(x / s) + z, qmin, qmax)
x_hat = s × (q - z)
```

s 是正的 scale，z 是 zero point；对称方案常固定零点，不同格式还有其他约定。教学设 s=0.1、z=0、x=0.26，则 q=3，反量化为 0.3，误差 0.04。若数值超过整数范围就被截断，误差不再只是四舍五入。

为什么不能把 float 直接强转 int？缩放把有限整数范围分配给数据范围，保留有用分辨率；直接截断会丢失大量小值。实现与格式见 [ONNX Runtime 量化文档](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)。

## 2. 离群值让同一个 scale 难以兼顾

一组权重大多在 -0.1 到 0.1，却有一个 10。若整个张量用同一 scale 覆盖 10，小值区间可用的格点很少，很多值被压成相同整数。若忽略 10，又会对离群值截断。

per-channel 或 group-wise scale 缩小共享范围，可能改善误差，但增加比例尺存储、布局和 kernel 复杂度。group 越小不是无成本越好；硬件是否有高效实现也影响实际速度。量化选择本质是在表示误差、元数据和执行成本之间分配预算。

## 3. PTQ 与 QAT 在不同阶段处理误差

PTQ 在训练后对模型量化，通常用代表性数据校准范围或优化量化参数；一些 weight-only 方法的流程又不同。QAT 在训练/微调中模拟量化影响，让参数适应误差，实际训练一般不是所有操作都直接用整数求梯度。

```text
PTQ：已有权重 → 校准/量化 → 评估
QAT：训练中模拟量化 → 参数适应 → 导出量化模型 → 评估
```

PTQ 成本通常更易接受，若任务质量不达标再评估更复杂方案；QAT 需要数据与训练资源，且训练模拟必须与部署算子匹配。校准集只含短英文，却上线长中文或图像任务，范围与敏感性可能不匹配。

## 4. AWQ 与 GPTQ 怎样利用额外信息

AWQ 根据激活统计识别对输出重要的权重通道，通过等价缩放等方式减小低比特权重量化误差；它不是简单保留最大绝对权重，也不是把所有激活都量成 4 bit。依据 [AWQ 论文](https://arxiv.org/abs/2306.00978)。

GPTQ 使用近似二阶信息进行逐层权重量化与误差补偿。直觉是某个权重量化造成输出偏差时，考虑输入相关性，调整尚未量化的部分，尽量控制层输出误差；并非独立把每个权重四舍五入。细节见 [GPTQ](https://arxiv.org/abs/2210.17323)。

两者都是方法族与生态入口，实际工具实现、group size、校准、层保留策略和 kernel 支持需固定版本。不能只看文件名含 AWQ/GPTQ 就断言质量和速度相同。

## 5. W4 不代表所有内存都减到四分之一

W4A16 表示权重和激活使用不同精度约定；weight-only 量化可能在计算中解包/反量化，未必完全使用整数矩阵乘。若硬件缺少适合 kernel，模型更小却不一定更快。

KV Cache 也不自动跟随权重精度变化。模型权重降为 4 bit，但 KV 仍可能是 16 bit，长上下文时缓存依然大；量化 KV 又有自己的误差、元数据与执行支持。相关缓存选项见 [Transformers KV cache](https://huggingface.co/docs/transformers/main/en/kv_cache)，预算公式见 [推理第 3 节](#/article/ai-inference?section=3)。
