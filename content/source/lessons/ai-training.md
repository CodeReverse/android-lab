## 1. 先判断缺的是知识、行为还是能力

训练是根据数据和损失更新参数，推理是用已有参数处理输入；具体一次更新可先看 [基础演算](#/article/ai-foundations?section=2)。预训练通常先从大规模数据学习通用模式，后训练再调整任务表现、指令遵循或偏好。SFT 是监督微调（Supervised Fine-Tuning），用示范输入输出继续训练；“微调”并不天然意味着改变所有参数。

客服模型不知道昨天更新的退货政策，直接微调并不一定合适：政策频繁变化，需要可追溯证据，检索通常更易更新。若模型知道政策，却始终不按指定格式回答，提示、结构化约束或 SFT 才更贴近问题。

```text
缺最新事实 → 优先评估检索/工具
缺稳定输出行为 → 提示与约束基线，再评估 SFT
已有多个答案但偏好不对 → 偏好数据与优化
需要可验证任务能力 → 数据、验证器与训练方案共同评估
```

这是工程选择顺序，不是定理。先保留不训练的基线，才能知道训练增加的成本是否必要；RAG 路线见 [检索增强](#/article/ai-rag-pipeline)。

## 2. SFT 把示范答案变成预测目标

监督微调提供输入 x 与目标输出 y，在通常的自回归目标下最小化目标 token 的负对数概率：

```text
loss = - Σ log pθ(y_t | x, y_<t)
```

教学例子里目标答案的关键 token 概率从 0.2 提高到 0.4，该 token 的损失从约 1.609 降到 0.916。真实训练包含完整序列、mask、批次与优化器，这个数字只解释目标函数，不代表模型整体质量提高。

示范数据决定模型学什么：若答案经常编造引用，模型也可能学会流畅编造。训练集与评测集需按来源、时间或任务隔离，防止近重复泄漏。格式准确与事实正确应分别评测，不能只看 loss 下降。

## 3. LoRA 为什么能减少可训练参数

对一个权重矩阵 W，不直接训练全部增量，而用低秩分解表示：`W' = W + sBA`。若 W 为 4096×4096，rank r=8，则 A/B 合计参数为 `8×4096 + 4096×8 = 65,536`，而原矩阵有 16,777,216 个参数；这里只比较一个矩阵，未算其他层。

冻结基础权重可以减少其梯度与优化器状态成本，但前向、反向所需激活等仍存在。rank 越小约束越强，省参数不保证所有任务质量不变。缩放系数、目标层、合并方式与工具实现要核对。机制见 [LoRA 原论文](https://arxiv.org/abs/2106.09685)。

若任务变化很大或低秩容量不足，可能需要更大 rank、更多适配层或其他训练方式；不能把 LoRA 当作全量微调的无条件等价替代。

## 4. QLoRA 进一步压缩冻结基座

QLoRA 把冻结的基础模型以低比特形式存储，在计算时按相应路径反量化，并训练低秩适配参数。论文引入 NF4、双重量化与分页优化器等设计，分别针对表示与内存压力。

它不是“所有梯度都用 4 bit 训练”，也不意味着最终部署引擎一定支持训练时那套格式。训练能加载、适配合并后能导出、移动引擎能高效执行，是三个不同验证点。依据 [QLoRA](https://arxiv.org/abs/2305.14314)；推理量化另见 [量化文章](#/article/ai-quantization)。

## 5. DPO 用偏好对调整相对概率

先区分两类数据：SFT 给“希望你输出什么”的示范；偏好数据给“同一个问题下，两个答案哪个更合适”的比较。偏好不必代表唯一正确答案，例如两个答案都正确但一个更简洁。DPO（Direct Preference Optimization，直接偏好优化）就是利用这类比较来调整模型，参考模型通常提供不希望偏离过远的基线。

对同一问题收集偏好答案 y+ 与较差答案 y−，DPO 通过相对参考模型的对数概率比构造优化目标。简化写法为：

```text
Δ = log(πθ(y+|x)/πref(y+|x)) - log(πθ(y-|x)/πref(y-|x))
loss = -log sigmoid(βΔ)
```

当模型相对参考模型更偏向 y+，Δ 增大，损失降低。β 调节目标中的尺度/约束权衡；这不是简单让所有好答案概率无限增大。DPO 在其假设下绕开显式奖励模型训练和相应在线 RL 流程，不代表不需要高质量偏好或能保证绝对正确。公式与假设见 [DPO 论文](https://arxiv.org/abs/2305.18290)。

偏好标注若偏爱冗长或迎合，模型就可能学到这些偏差。事实、格式、帮助性与安全不能被一个模糊“更好”完全替代。

## 6. GRPO 依赖一组输出和可信奖励

强化学习把模型看成策略：它在给定输入下选择输出，环境或验证器对结果给奖励，训练提高取得较好奖励的行为倾向。reward 是评分，advantage 是相对基线“好多少”，不是同一个量。GRPO（Group Relative Policy Optimization）使用同题一组结果构造这个比较基线；KL 约束则用来限制策略相对参考分布的偏离，不能把它当事实正确性的保证。

GRPO 对同一输入采样一组候选，用组内奖励统计构造相对优势，并结合策略更新约束。以教学奖励 `[0,0,1,1]` 为例，均值 0.5，标准差 0.5，标准化后优势为 `[-1,-1,1,1]`；真实实现还需数值稳定、token/序列归一化、裁剪与 KL 等细节。

组内比较减少对独立价值模型的依赖，但采样成本、奖励可靠性和奖励投机仍存在。所有候选奖励相同时，这个组难以提供区分信号；答案验证器不完整时，模型可能学会通过检查而未完成真正任务。原方法见 [DeepSeekMath / GRPO](https://arxiv.org/html/2402.03300v3)，不要把后续所有变体混称完全相同算法。

## 7. 用任务收益而不是训练术语验收

先保存基线，再比较提示改进、RAG、小规模适配与更复杂训练。评测覆盖目标任务、未训练通用任务、错误拒答、引用和成本；看是否发生遗忘或偏差放大。训练 loss、偏好胜率与业务成功率各有边界。

记录数据版本、模型、tokenizer、适配器与评测配置，避免把不同基座的改动混在一起。本文是目标函数和参数量演算，没有宣称训练过模型；评估方法见 [AI 质量工程](#/article/ai-quality)。
