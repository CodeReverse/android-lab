## 1. 同一个问题为什么需要两种召回

用户可能搜索精确错误码 `E_AUTH_17`，也可能问“登录失效后如何恢复”。前者强调字符和符号匹配，后者需要跨表达方式找相似含义。纯向量可能忽略细微编号，纯关键词可能漏掉同义表达，因此先按查询类型建立基线，再评估混合召回。

检索返回相关候选，不保证答案真实或权限正确。版本与访问范围需在完整 [RAG 链路](#/article/ai-rag-pipeline?section=3) 中处理。

## 2. BM25 为什么不是数关键词次数

BM25 结合词项区分度、出现频率饱和与文档长度归一化。一个常见形式为：

```text
score(q,d) = Σ IDF(t) × tf(t,d)(k1+1)
                         / [tf(t,d)+k1(1-b+b·len(d)/avgLen)]
```

公式为标准形式说明，具体实现的 IDF、分词和参数默认值需核对版本。设文档长度等于平均长度、k1=1.2，则 tf=1 的频率项为 1；tf=4 时为 `8.8/5.2≈1.69`，不是 4 倍。重复堆词不会线性增益。长度项则避免长文只因包含更多词就总占优。

罕见错误码通常比常见词更有区分力，但中文分词、字段权重和符号切分直接影响结果。可对照 [Lucene BM25Similarity 源码](https://github.com/apache/lucene/blob/releases/lucene/9.12.0/lucene/core/src/java/org/apache/lucene/search/similarities/BM25Similarity.java)，该 Lucene 实现会省去对排序无影响的公共缩放因子，不能把上面的教学分数当作它的逐位输出；也不能把公式当成无需调试分析器的保证。

## 3. 向量把匹配变成几何距离

先手算一个只用于说明几何的例子：query=[1,0]，候选 A=[0.8,0.6]、B=[0,1]，三者长度都是 1。query 与 A 点积为 0.8，与 B 为 0，因此按余弦 A 更接近。真实 embedding 的每一维通常不能直接命名为“Android 程度”或“语义正确度”；是训练目标让某些任务中的距离有用，二维数字只解释计算。

Embedding 将 query 与文档映射到同一模型约定的向量空间，按点积、余弦或距离检索。若模型训练目标与任务不匹配，几何接近也可能业务无关；对精确版本、数字与否定尤其需要评测。

归一化向量时点积等于余弦；未归一化则向量长度也会影响点积。索引和 query 应使用兼容模型、预处理和度量。不同 embedding 版本不能默认混用，即便维度刚好相同。

## 4. HNSW 用图导航减少逐一比较

暴力检索将 query 与所有向量比较，数据大时成本高。HNSW 构建分层近邻图：高层较稀疏，用较大跨度接近目标区域，再到低层扩大候选搜索。

```text
高层：入口 → 较接近节点 → 下移
低层：维护候选集与当前较优结果
      扩展尚有希望的邻居，满足停止条件后返回近邻
```

这是机制伪图，不是完整实现。它通过近似搜索换速度，可能漏掉真实最近邻。M 影响图连接与内存/导航，efConstruction 影响建图搜索，efSearch 影响查询探索；增大探索通常提高召回但增加延迟，具体行为依实现。原理见 [HNSW 论文](https://arxiv.org/abs/1603.09320)。

用一小份数据的暴力结果作近邻基准，测 ANN recall 与延迟，才知道损失多少。注意这与“是否找到了人工标注的正确证据”是两种 recall：前者评价近似索引，后者评价任务检索。

## 5. RRF 用排名融合，避免硬加不同量纲分数

BM25 的 12 分与余弦 0.8 不在同一量纲，直接相加没有天然解释。RRF 按各路名次累加 `1/(k+rank)`。教学取 k=60，文档 A 在两路排 1、10，得分约 `1/61+1/70=0.03068`；B 排 3、3，约 `2/63=0.03175`，B 因两路都靠前而略高。

这不是语义正确性的保证，也不是 k 必须取 60。候选窗口、缺失文档与排名噪声都会影响结果。机制参考 [Elasticsearch RRF](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)。

## 6. Reranker 把更贵的判断留给少量候选

双塔 embedding 可提前计算文档向量，便于大规模召回；cross-encoder 类重排将 query 与候选共同输入，能建模更细交互，但每对都需计算。通常先便宜召回，再对有限候选重排，而不是对全库逐条运行昂贵模型。

验证时分别看“正确证据是否进入候选”“进入后是否排到前面”“最终上下文是否保留条件”。若候选池里根本没有正确段落，重排再强也无法凭空补回。本文数值为公式演算，没有实际索引性能结果；完整质量体系见 [AI 质量工程](#/article/ai-quality)。
