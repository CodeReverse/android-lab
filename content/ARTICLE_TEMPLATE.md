# 学习文章与面经详解的写作规范

## 先区分文章用途

- **学习文章、学习路径知识点及其他非面经技术文章**：正文采用连续讲解，不用问答串、面试官口吻或“第 N 问”。面经仅提供选题线索时仍属于学习文章。
- **明确的面经详解**：保留原题概述、逐题参考答案和事实边界；不把编辑追问冒充公司原题。
- 学习路线是阅读索引，链接到具体文章和小节，不重复整篇教程。

## 学习正文的推进顺序

从概念和用途开始，解释组成与职责，再用一次具体操作串起运行过程，继续展开实现机制、失效边界和验证。用依赖关系推进深度，不以问答数量或篇幅表示深度。

每节集中讲一个主题，标题用陈述语，例如“状态写入与阶段失效”。优先保留关键因果、一段执行过程和必要反例；删除重复定义、空泛提示和多次声明。公式、代码、表格只用于解释难点。

通常 4–8 个小节，正文约 1000–2500 个中文字符；复杂主题可略长，但每节保持短段落。需要展开更多机制时拆为关联文章。资料链接、表格代码与文末提炼不机械计入字数目标；不能为达到下限而注水。

```markdown
## 1. 概念与职责

直接定义技术，说明它解决的问题和适用范围。

## 2. 组成与执行过程

用一个输入说明状态、数据或调用怎样在组件之间流转。

## 3. 实现机制

解释支撑行为的数据结构、算法或同步方式；区分契约与版本实现。

## 4. 边界与验证

给出一个反例以及可观察的证据。没有执行的实验标为验证设计。

## 原理资料

列出支持本文机制的资料与版本范围。

## 面试提炼

1. 一个基础概念问题。（回看第 1 节）
2. 一个执行或实现问题。（回看第 2–3 节）
3. 一个反例、取舍或验证问题。（回看第 4 节）
```

文末选 3–5 个问题覆盖基础、机制、边界和验证，不重复正文答案。问题应能从正文找到解释；有原帖选题时，可在末尾另附简短原题对应说明。文末自测不要求开启练习功能。

## 深度与事实边界

- 先讲公共契约，再讲固定版本的实现；区分 JVM 规范、HotSpot 和 ART。
- 保留成立条件和反例，如超时不代表未提交、可见不代表原子。精简不能删掉关键条件。
- 原帖证明问过什么；官方资料、规范和论文支持机制。没有确认的源码细节应标明待核验。
- 区分发布时间、面试日期和采集时间；不推断未经样本支持的行业频率。
- 没有执行的实验不能写成实测成果；技术更新保留 ID，递增 version，更新 updated。

## 构建与维护

正文在 `content/source/lessons/`，元数据在 `content/articles.json`，路径在 `content/learning-paths.json`。构建推导 `sectionCount` 和 `reviewCount`，检查小节顺序、文末自测与路径定位；结构通过不代表事实核验完成。明确面经的 `questionCount` 维持独立统计。

执行 `npm run content:sync`、`npm test`、类型检查与构建。人工核验内容后再发布。
